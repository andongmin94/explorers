# Git 탐색기

두 브랜치에서 같은 제목 줄을 수정하고, 병합 충돌을 해결해 두 부모를 가진 커밋까지 만드는 한국어 학습 앱입니다.

## 실행

이 탐색기는 [탐색기 모음](../README.md)의 한 페이지입니다. 저장소 루트에서 `npm run dev`를 실행한 뒤 <http://127.0.0.1:5173/git/>을 엽니다. 검사는 루트의 `npm test`로 모든 탐색기를 함께 실행합니다.

## 대표 시나리오

하나의 로컬 저장소에 `welcome.txt`가 있습니다. 공통 조상 C0에서 제목은 `오늘의 산책을 시작하세요`입니다.

| 사건 | 조작                            | 관찰할 변화                                     |
| ---- | ------------------------------- | ----------------------------------------------- |
| 0    | 시작                            | HEAD → main → C0, 파일·index·커밋의 내용이 같음 |
| 1    | `git switch -c feature/title`   | 같은 C0에 새 브랜치 생성, HEAD 전환             |
| 2–4  | 제목 수정 → `git add` → 커밋    | `나만의 산책을 찾아보세요`를 담은 C1 생성       |
| 5    | `git switch main`               | C0의 내용으로 파일과 index 복원, C1은 보존      |
| 6–8  | 같은 줄 수정 → `git add` → 커밋 | `우리 동네를 함께 걸어요`를 담은 C2 생성        |
| 9    | `git merge feature/title`       | 동일한 줄의 충돌, 새 커밋 없이 main → C2 유지   |
| 10   | 최종 문장 선택                  | 작업 파일의 충돌 표시 제거, index는 아직 미해결 |
| 11   | `git add welcome.txt`           | 해결 내용을 index에 등록, 병합 커밋 대기        |
| 12   | 병합 커밋                       | C2·C1을 부모로 갖는 C3 생성, main → C3          |

충돌 해결은 두 문장을 합치기, main 유지, feature/title 유지 중에서 선택합니다. 세 선택 모두 Git에서 가능한 해결입니다. 어느 문장이 제품에 맞는지는 사람이 결정합니다. 한쪽 문장을 선택해도 C3는 두 이력을 연결하는 병합 커밋입니다.

## 화면에서 구분하는 상태

- **작업 파일:** 사람이 지금 수정하는 내용입니다.
- **스테이징(index):** 다음 커밋에 넣을 내용입니다. 커밋 뒤에는 비워지는 것이 아니라 커밋과 같은 내용을 가집니다.
- **커밋 이력:** 기록된 스냅샷과 부모 관계입니다. 이 시나리오에서 커밋을 만들 때 현재 브랜치가 앞으로 이동합니다.
- **충돌 중 index:** 공통 조상(stage 1), 현재 쪽(stage 2), 가져올 쪽(stage 3)의 세 버전을 보관합니다. 작업 파일만 편집해도 이 상태는 유지되며, `git add`가 해결 내용을 등록합니다.

HEAD는 이 시나리오에서 현재 브랜치를 가리킵니다. 브랜치 전환은 수정 사항을 커밋한 깨끗한 상태에서 실행합니다. 표시한 명령과 상태는 학습용 모델이며 터미널을 대신 실행하지 않습니다.

## 범위와 소스

첫 수업은 로컬 브랜치 두 개, 파일 하나, 텍스트 충돌 하나에 집중합니다. 원격 저장소·push/pull·rebase·fast-forward·삭제/이름 변경 충돌은 다루지 않습니다. C0–C3는 읽기 쉬운 학습용 이름이며 실제 Git 해시가 아닙니다. 장치 사이의 내용 이동은 저장 상태의 변화를 설명하는 표현이며 실제 Git 내부의 물리적 구조나 처리 시간을 나타내지 않습니다.

`src/engine.js`는 사건별 독립 상태, `src/scene.js`는 이력과 파일·index의 표시 및 이동, `src/main.js`는 재생과 해결 선택, `src/lesson.js`는 해설과 학습 근거를 담당합니다. 로컬 Pretendard와 자체 SVG·CSS로 중립색 네오브루탈 화면을 구성합니다.

## 검증

Node 기본 테스트 7개로 브랜치 포인터, 인덱스, 병합 부모, 해결안별 파일과 스냅샷 독립성을 검사합니다. 별도 임시 저장소에서 실제 Git CLI로 세 해결안을 검산해 충돌 표식, index의 세 버전, HEAD 유지, 두 부모 병합 커밋이 모델과 일치함을 확인했습니다.

브라우저에서는 처음부터 충돌까지 자동 재생, 해결 선택과 병합 완료, 세 해결안 비교, 예측 문제, 이동 중 정지·재개·시킹, 360px·390px 모바일과 밝은·어두운 테마를 확인했습니다.

## 학습 근거

- [Pro Git — Branches in a Nutshell](https://git-scm.com/book/en/v2/Git-Branching-Branches-in-a-Nutshell): 브랜치 포인터, HEAD, 브랜치 전환과 파일 내용.
- [Pro Git — Basic Branching and Merging](https://git-scm.com/book/en/v2/Git-Branching-Basic-Branching-and-Merging): 공통 조상, 충돌 표시, 해결 후 병합 커밋.
- [git-add](https://git-scm.com/docs/git-add): index에 현재 파일 내용을 등록하는 동작.
- [git-merge — True Merge](https://git-scm.com/docs/git-merge#_true_merge): 충돌 시 HEAD 유지와 index의 세 버전.
