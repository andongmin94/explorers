# 디스크 스케줄링 탐색기

같은 8개 디스크 요청을 FCFS와 SSTF로 처리하며 헤드 이동 경로와 거리를 비교하는 한국어 학습 앱입니다.

## 실행

이 탐색기는 [탐색기 모음](../README.md)의 한 페이지입니다. 저장소 루트에서 `npm run dev`를 실행한 뒤 <http://127.0.0.1:5173/disk/>을 엽니다. 검사는 루트의 `npm test`로 모든 탐색기를 함께 실행합니다.

## 대표 시나리오

실린더 범위는 0–199, 시작 헤드는 53입니다. 요청 `[98, 183, 37, 122, 14, 124, 65, 67]`이 모두 실행 전에 도착했습니다.

| 방식 | 처리 순서 | 총 이동 거리 |
| --- | --- | ---: |
| FCFS | 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67 | 640칸 |
| SSTF | 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183 | 236칸 |
| (참고) LOOK, 바깥쪽 먼저 · 끝 요청 14에서 돌아옴 | 37 → 14 → 65 → 67 → 98 → 122 → 124 → 183 | 208칸 |
| (참고) SCAN, 바깥쪽 먼저 · 실린더 0까지 감 | 37 → 14 → (0) → 65 → 67 → 98 → 122 → 124 → 183 | 236칸 |

LOOK과 SCAN은 비교 대화상자와 정리에서만 언급합니다. SCAN 계열의 핵심은 한 방향으로 쓸어 먼 요청의 기아를 막는 것입니다(OSTEP 37.5).

각 요청은 **OS가 큐에서 선택 → 컨트롤러가 받아 실행 → 헤드 이동 → 도착·합산**으로 재생합니다. 이동 거리는 `|목표 실린더 − 현재 실린더|`이며 도착 시 누적됩니다. 대기 큐는 원래 도착 순서를 유지하고 선택·처리 완료 표시를 바꿉니다. HDD의 팔은 고정된 축을 중심으로 회전하며 선택한 실린더에 헤드를 놓습니다.

학습은 공통 모델(목표 → 관찰 → 예측 → 확인 → 설명 → 비교 → 정리)을 따릅니다. 시작 화면은 질문과 학습 목표만 보여 주고 결과를 미리 말하지 않습니다. "핵심 장면에서 멈추기"는 장면 탭의 핵심 장면에서 재생을 멈추고, "다음 요청"은 한 요청씩 진행합니다. 예측은 실린더 번호만 적힌 선택지에 선택지별 이유를 붙이고, "핵심" 메모는 요청마다 바뀝니다. 끝나면 해설 탭에 정리(핵심 정리, 확인 문제, 학습 진도, 다음 실험)가 나옵니다. 기록에는 아직 처리하지 않은 결과를 표시하지 않습니다.

## 모델의 범위

- 이동 거리 비교이며 실제 탐색 시간·회전 대기·전송 시간 또는 응답 시간은 계산하지 않습니다.
- 새 요청이 계속 도착하는 실행을 모델링하지 않습니다. SSTF의 기아 가능성은 별도 개념 설명이며 이 유한한 요청 묶음에서는 모든 요청이 완료됩니다.
- 거리가 같으면 원래 도착 순서가 빠른 요청을 선택합니다.
- 실제 논리 블록 주소와 물리 디스크 위치의 배치는 이 교육용 실린더 모델보다 복잡합니다.
- SSD에는 이 모델의 기계적 헤드 탐색이 없습니다.
- 팔의 움직임은 위치 관계를 보여 주는 투영도이며 실제 디스크 부품의 치수나 지연 측정값이 아닙니다.

## 구현과 검증

`src/engine.js`는 각 선택의 이전·이후 상태를 계산합니다. `src/scene.js`는 대기 큐와 투영된 HDD, 취소·일시정지 가능한 애니메이션을 담당합니다. `src/main.js`는 해설·예측·재생·기록을 연결합니다. 로컬 Pretendard와 자체 SVG를 사용합니다.

Node 기본 테스트 러너로 FCFS 순서·거리, SSTF의 매 선택 최단 거리·합계, 동률·중복 요청 처리 및 이전 상태 보존을 검사합니다. 외부 브라우저 검증 프레임워크는 포함하지 않습니다.

학습 근거: [OSTEP — Hard Disk Drives, 디스크 구조·탐색·스케줄링](https://pages.cs.wisc.edu/~remzi/OSTEP/file-disks.pdf).
