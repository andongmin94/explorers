# CPU 스케줄링 탐험가

세 프로세스가 하나의 CPU를 나누는 대표 시나리오를 실행·예측·비교하는 한국어 학습 앱입니다. Protocol Explorer와 분리된 프로젝트이며 별도의 개발 서버·의존성·Git 저장소를 사용합니다. 원래 프로젝트에 대한 런타임 의존성은 없습니다.

## 실행

Node.js 22.12 이상에서 실행합니다.

```powershell
npm.cmd install
npm.cmd run dev
```

개발 주소: http://127.0.0.1:5174/

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

빌드는 `dist/`에 생성되고 빌드 미리보기는 4174 포트를 사용합니다. 기존 Protocol Explorer의 5173 포트는 사용하지 않습니다.

## 대표 시나리오

| 작업 | 도착 | 작업 순서 |
| --- | --- | --- |
| P1 · 문서 미리보기 | 0ms | CPU 5 → 입출력 4 → CPU 3 |
| P2 · 파일 검색 | 1ms | CPU 2 → 입출력 3 → CPU 2 |
| P3 · 수식 계산 | 2ms | CPU 4 |

라운드 로빈의 시간 할당량을 1~5ms로 변경하거나 FCFS로 바꿀 수 있습니다. 입력이 바뀌면 준비 큐·장치 상태·애니메이션·시간표·설명·통계를 같은 시뮬레이션 결과에서 다시 계산합니다.

대표 RR 2ms 실행 순서:

```text
P1 0–2 → P2 2–4 → P3 4–6 → P1 6–8
→ P3 8–10 → P2 10–12 → P1 12–13
→ CPU 유휴 13–17 → P1 17–19 → P1 19–20
```

| 검산 지표 | RR · 2ms | FCFS |
| --- | ---: | ---: |
| 평균 최초 응답 | 1ms | 3ms |
| 평균 준비 큐 대기 | 5.33ms | 5ms |
| 평균 반환 시간 | 13ms | 12.67ms |
| 전체 완료 시각 | 20ms | 16ms |
| CPU 활용률 | 80% | 100% |
| 작업 간 전환 | 6회 | 4회 |

학습의 핵심은 **응답이 빠르다고 전체 완료도 빨라지는 것은 아니다**입니다. t=7의 I/O 복귀는 이미 기다리는 P3를 추월하지 않습니다. t=13~17에는 P1의 입출력을 기다리므로 CPU가 쉬지만, 이 시간은 준비 큐 대기로 세지 않습니다.

## 조작

- 재생·일시정지, 1ms 앞뒤 이동, 다음 사건, 초기화, 0.5×/1×/2× 속도
- 시간 슬라이더·시간표 눈금·사건 기록·핵심 장면을 눌러 탐색
- 다음 CPU 작업 예측 후 실제 준비 큐 순서와 비교
- 두 알고리즘의 전체 시간표와 6개 지표 비교
- Space: 재생·정지 / ←·→: 1ms 이동 / R: 초기화
- 모바일 배치, 밝은·어두운 테마, 동작 줄이기 설정 지원

## 모델의 범위

CPU는 하나, I/O는 서로 독립적으로 진행되며 문맥 교환 비용은 0ms로 가정합니다. 같은 경계 시각에는 CPU 구간 종료를 처리한 뒤 도착·I/O 복귀 작업을 입력 순서대로 준비 큐에 넣고, 시간 할당량이 끝난 작업을 마지막에 넣습니다. 이것은 동시 사건을 재현하기 위한 이 모델의 규칙이며 모든 운영체제의 규칙이라는 뜻은 아닙니다.

프레임 t는 경계 사건 처리 후, `[t, t+1)` 실행 전의 상태입니다. 최초 응답은 첫 실행−도착, 반환 시간은 완료−도착, CPU 대기는 준비 큐에 머문 누적 시간입니다. 작업 전환은 서로 다른 프로세스 사이만 세고 최초 배정·유휴 진입·같은 작업의 재배정은 제외합니다.

실제 운영체제를 구동하거나 실제 실행 시간을 측정하는 앱은 아닙니다. 같은 작업을 동일한 규칙으로 재현하는 교육용 시뮬레이터입니다.

## 소스 구성

| 파일 | 역할 |
| --- | --- |
| `src/engine.js` | 순수 함수 기반 RR·FCFS 계산, 프레임·사건·통계 |
| `src/scene.js`, `src/scene.css` | CPU 그림, 프로세스 이동, 상태별 배치 |
| `src/lesson.js` | 실제 사건에 따른 해설과 핵심 장면 |
| `src/main.js` | 재생·탐색·예측·비교 UI, 시간표와 사건 기록 |
| `src/styles.css` | 네오브루탈 Mono·Pretendard·반응형 스타일 |
| `test/engine.test.js` | 수동 검산, FIFO 순서, CPU 보존, 지표·대기·유휴 검사 |

11개 엔진 검사를 통과했습니다. 브라우저에서는 RR 1~5ms·FCFS의 최종 지표, 실제 재생·정지·되감기·예측·비교, 데스크톱·태블릿·모바일과 다크 모드를 확인했습니다. 초기·유휴·완료 상태와 동작 줄이기도 확인했습니다.
