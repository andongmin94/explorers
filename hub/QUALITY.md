# 모바일 재생 중 초기화·전환 수정 확인

320×568과 390×844의 모바일 Chromium 터치 환경에서 단계 해설을 가리고, 사건이 진행 중일 때 초기화하거나 조건을 바꿨다. 카드가 사라지거나 이동을 시작하는 순간의 화면과 사건이 끝난 뒤의 기록을 비교했다. [실제 재생 화면 9장](scene-comparison.jpg)

| 탐색기 | 다시 실행한 장면 | 확인한 결과 |
| --- | --- | --- |
| 메모리 | FIFO 4회 완료 → 5번째 D 조회 중 LRU 선택 | 조건이 접히고 D 조회가 화면에 보인다. A/B/C에서 B의 마지막 사용 2번째가 강조되고, F1이 빈 뒤 SSD의 D가 들어간다. CPU가 값을 받으면 기록이 4회에서 5회가 되고 RAM은 A/D/C다. 정지 중에 바꾸면 새 조회도 정지해 있고, 재개 후 수동은 5회에서 멈추고 연속은 6회로 넘어간다. 초기화한 CPU에는 ‘시작 전’, 반환선에는 ‘값 반환’이 보인다. |
| 프로토콜 | IMAP 마지막 a4 OK 이동 중 처음으로 | 개요의 첫 화면 프레임에서 시퀀스 스크롤은 0, 첫 화살표는 TCP SYN이다. 1.5초 후에도 위에 머물렀고, 네트워크 보기에서 초기화한 뒤 시퀀스를 열어도 같다. SSH로 전환하면 새 시나리오의 SYN이 보인다. 320px에서 IMAP 사서함 제목과 보기 탭 사이에는 10px 간격이 생겼다. |
| Git | C3 생성 도중 ‘다른 해결안으로 비교’, 병합을 마친 뒤 결과 탭에서 ‘다른 제목을 선택해 결과 비교’ | 두 진입점 모두 제목과 세 버튼이 한 화면에 보이고 첫 버튼에 포커스가 간다. 320px에서 버튼은 y223~445, 390px에서는 y361~583에 있었다. 기록 9건, 커밋 3개, 인덱스의 충돌 버전 3개가 복원된다. 다른 제목을 선택해 작업 파일에 반영되는 것까지 확인했다. |
| CPU | FCFS 마지막 P2 완료 이동 중 처음으로, RR 2ms 계기판 | 두 폭 모두 새 0ms 시계와 P1 배정, P2·P3의 도착 예정 카드가 한 화면에 있다. 320px에서 RR의 시간 만료 배지와 계기판 사이 4px, 할당량 막대와 입출력 요청 사이 11px를 확보했고 ‘시간 할당량’은 한 줄로 보인다. |
| 디스크 | SSTF의 122→124 이동 중 FCFS로 전환, 비교 창에서 다시 SSTF로 전환 | 설정이 닫히고 그림에 현재 규칙, 요청 8개, 헤드 53과 누적 0칸이 함께 보인다. 설정 창과 비교 창 어느 쪽에서 들어가도 초기화가 동일하다. 첫 요청까지 재생해 FCFS가 98, SSTF가 65를 고르는 것을 확인했다. |

수정한 다섯 탐색기의 기존 자동 검사 66개가 통과했다. 여섯 탐색기를 통합 빌드한 뒤 실제 미리보기 주소에서도 D 교체 기록, IMAP 첫 화살표, Git 세 선택지, CPU 초기 배정, 디스크의 규칙 전환과 첫 요청을 확인했다.
