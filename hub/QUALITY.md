# 모바일에서 다시 재생한 여섯 탐색기

[수정 후 실제 재생 화면 여섯 장](scene-comparison.jpg). 2026년 11월 11일, 해설과 기록 표를 가린 모바일 Chromium에서 지난 검수와 같은 버튼·사건을 다시 재생했다. 화면 위치 검사는 캡처를 위해 그림으로 스크롤하지 않고, 학습자가 ‘다음’이나 예측 확인 버튼을 누른 위치에서 시작했다. 장치 이름, 경로, 숫자는 그림에 그대로 남겼다.

| 탐색기 | 다시 보는 방법 | 그림에서 확인한 결과 |
| --- | --- | --- |
| 메모리 | FIFO에서 7번째 접근 뒤 다음 E의 교체 대상을 예측하고 D 선택 → 실제 교체 확인 | 먼저 그림으로 돌아오고, 적재 시각 5인 D 선택 → 프레임 교체 → E 적재와 재시도가 차례로 보인다. 360×740과 390×844에서는 그림 664px 전체가 교체 내내 보였다. 320×568에서도 SSD→RAM 카드가 화면을 벗어나지 않는다. 첫 A 적재는 SSD의 B·C를 지나지 않으며, 320px의 ‘조회’와 ‘접근 완료’도 RAM 제목·F1과 떨어져 있다. |
| CPU | 라운드 로빈, 시간 할당량 1ms, 7ms에서 다음 1ms | 320×568에서 P2가 SSD에서 복귀하고 P1이 큐 뒤로 간 다음, P3가 큐에서 CPU로 들어간다. 마지막 이동 때 준비 큐와 CPU 칩이 함께 보인다. 다른 카드가 당겨지는 중에는 ‘큐 뒤’ 안내가 카드 밑에서 먼저 나타나지 않는다. 13ms의 ‘입출력 2 ms 남음’도 P1 카드 안에 들어간다. |
| 트랜잭션 | 일반 읽기 9번째, 잠금 읽기 7번째, 교착 7번째의 예측을 각각 확인. 교착 1·2번째 시작, 6번째 A 요청, 10번째 커밋 재생 | 세 예측 모두 320·360·390px에서 첫 프레임부터 그림이 보인다. 롤백할 때 T2의 미확정 19는 사라지지만 B의 확정 20과 T1의 미확정 9는 남는다. BEGIN·COMMIT은 DB 공통 포트, A·B 쓰기는 각 행 포트를 사용한다. 마지막 커밋이 도착해야 A 10→9·B 20→19가 함께 확정된다. T2의 A 요청은 T1의 B 대기 표시를 지나지 않고, 320px에서도 ‘T2 보유’가 한 줄에 남는다. |
| 프로토콜 | DNS 4단계 권한 서버 응답 → 5단계 클라이언트 회신, TLS 3단계 인증서 수신 | DNS는 이동 표식과 고정 응답 카드를 분리했다. 320·390px 모두 리졸버와 주소가 보이며 A·TTL·AA를 아래에서 읽을 수 있다. 응답이 도착한 순서대로 리졸버와 클라이언트에 캐시 표식이 붙는다. TLS는 암호화된 전송을 마친 뒤 클라이언트에서 서버 인증서 → 중간 인증기관 → 기기 신뢰 루트를 확인한다. 검증 중 일시정지하면 사슬도 멈추고 재개하면 이어진다. |
| Git | main 편집 → add → C2 커밋, 충돌에서 ‘두 의도를 합치기’ → 등록 → C3 커밋 | 세로 화면에서 add는 작업 파일과 스테이징 사이로, C2·C3 표식은 스테이징에서 작업 파일 옆을 따라 저장소로 이동한다. 320·390px 모두 커밋 이동 중 작업 카드를 덮은 프레임이 없었다. 320×568에서도 도착 후 HEAD → main, C3, 부모 C2·C1이 한 화면에 보인다. |
| 디스크 | SSTF 5번째 14→98, 두 줄 큐 아래에서 출발하는 2번째 요청도 재생 | 선택 카드는 자기 칸에서 줄 사이로 빠져나간 뒤 가운데 통로를 따라간다. 320·390px에서 다른 요청 칸과 겹친 프레임이 없었다. 320×568의 다음 버튼에서 시작해도 카드가 끝까지 보인다. 5번째에는 후보 122까지 108칸과 선택 98까지 84칸이 보이고, 도착 후 누적값이 67→151칸이 된다. |

**통합본 확인.** 여섯 앱을 한 번에 빌드하고 실제 통합 주소에서 앱마다 대표 사건을 재생했다. 360px FIFO 교체 장면은 664px, 390px 교착 롤백은 628px가 보였다. 320px에서는 CPU의 P3 배정, 디스크의 98 도착, Git의 C3와 두 부모를 확인했다. 390px DNS 권한 응답은 아래 카드에 A 203.0.113.10, TTL 3600초, AA를 표시했다.

**검사 범위.** 기존 테스트 82개(프로토콜 26, CPU 17, 메모리 11, 트랜잭션 18, 디스크 3, Git 7)가 통과했다. 주 화면은 320×568·390×844, 퀴즈 복귀는 360×740도 사용했다. 프로토콜의 좁은 화면은 320×690이다. 모바일 검증은 Chromium 터치 에뮬레이션으로 수행했으며 실기기 Safari 검사는 포함하지 않았다.
