# 모바일 재생 중 초기화·전환 검수

통합 미리보기를 모바일 Chromium 터치 환경에서 열었다. 기본 크기는 320×568, 390×844이고 프로토콜은 320×690에서도 확인했다. 단계 해설을 가리고 카드가 이동할 때 초기화하거나 조건을 바꿨다. 전환 직후와 원래 사건이 끝날 시간을 넘겨 다시 관찰했다. 그림을 먼저 보고 기록 행, 카드 위치, 프레임 값, 잠금 소유자를 대조했다. [320px 재현 화면 모음](scene-comparison.jpg)

## 남은 문제

| 순서 | 재현 | 관찰과 수정 기준 |
| --- | --- | --- |
| 1 | 메모리 FIFO 4회 완료 → 5번째 D 조회 중 LRU 선택 | 두 폭 모두 직전까지 4행·A/B/C였다. 전환 한 번에 5행·A/D/C가 되고 D 이동 카드가 사라졌다. LRU 계산 결과는 맞지만 B 퇴출을 한 번도 보여주지 않고 해당 접근을 완료 처리한다. 마지막 완료 접근을 기준으로 바꾸고 5번째를 새 정책으로 재생할 수 있어야 한다. |
| 2 | IMAP 시퀀스 5단계, 마지막 `a4 OK` 이동 중 처음으로 | 새로 연 같은 개요는 첫 TCP 연결부터 보이지만 초기화한 개요는 2초 뒤에도 16~18번만 보였다. 시퀀스 내부 스크롤이 320에서 984px, 390에서 920px에 남았다. 두 개요 모두 전체 18개를 담고 있으며 손상된 기록은 없다. 초기화하면 같은 첫 화살표가 보여야 한다. |
| 3 | Git에서 ‘main 문장 유지’ 후 C3 생성 중 ‘다른 해결안으로 비교’. 병합을 끝낸 뒤 결과 탭의 ‘다른 제목을 선택해 결과 비교’로도 확인 | C3 이동 취소, 충돌의 세 버전, 기록 9건은 맞았다. 전환 후 스크롤은 파일 비교 또는 병합 결과에 남고 선택지는 위로 밀려났다. 320px 결과 탭에서는 마지막 선택지 하단도 화면 위 33px였다. 재선택 직후 해결안 버튼이 보이면 다음 행동이 분명하다. |
| 4 | CPU FCFS 15→16ms의 P2 완료 이동 중 처음으로 | 기록과 작업은 0ms로 돌아왔다. 320에서는 이전 스크롤 430px가 남아 P1만 화면 맨 위에 걸리고 시계·CPU·P2/P3의 도착 예정 카드가 안 보인다. 390에서도 도착 예정 카드가 잘린다. 초기화 뒤 첫 배정과 도착 예정 작업을 함께 보여줘야 한다. |
| 5 | CPU RR의 320px 계기판 | ‘시간 만료’와 CPU 구간 표시가 겹치고 ‘할당량’의 마지막 글자가 혼자 줄을 넘는다. 할당량 막대와 ‘입출력 요청’ 배지는 세로로 5px 겹친다. |
| 6 | 디스크 SSTF 7번째 122→124 이동 중 FCFS 선택 | 320px에 조건 패널과 조작줄이 남는다. 큐는 위에서 599px, 헤드는 930px부터다. 조건을 접으면 두 정책의 0단계 그림도 같아서 적용한 규칙을 읽을 수 없다. 그림 안에 선택된 규칙을 표시하면 첫 요청을 실행하기 전에도 구별할 수 있다. |
| 7 | 메모리 처음으로 직후 | CPU 요청의 ‘시작 전’ 아래 반환 경로에 ‘접근 완료’가 상시 표시된다. 완료 상태로 오해하기 쉬워 경로의 역할인 ‘값 반환’으로 읽히게 하는 편이 명확하다. |

## 전환 후 정상으로 확인한 상태

- **프로토콜** — POP3의 QUIT와 SSH 에코 도중 초기화, IMAP 새 메일 통지 중 SSH 전환에서 이전 패킷·기록이 다시 생기지 않았다. 알림이 이동하는 동안 서버 3통·노트북 2통이 각각 보였다.
- **메모리** — FIFO의 8번째 E 적재 중 초기화하면 빈 프레임 3개, 미상주 5개, 0회로 돌아오고 2.8초 후에도 그대로였다.
- **트랜잭션** — 일반 SELECT의 9번째 커밋에서 T2가 기다릴 때 초기화, T2 쓰기 이동 중 잠금 모드 전환, 재고 갱신과 교착의 양방향 전환, 교착 6번째 T2의 A 요청 중 초기화를 확인했다. 재고 초기값·잠금·미확정 값·기록이 새 장면과 일치했다. 교착 직전 T1의 A 보유/B 대기, T2의 B 보유/A 요청은 그림에서 구분됐다.
- **CPU·디스크** — FCFS 완료 직전 초기화와 RR 전환에서 CPU 작업·기록이 복원됐다. 디스크의 SSTF 67→37 탐색 중 초기화와 122→124 탐색 중 FCFS 전환 후에는 헤드 53, 누적 0칸, 대기 8개, 기록 0건이었다. 새 FCFS를 재생하면 첫 요청 98이 이동했다.
- **Git** — 브랜치 전환 중 C0 복원을 취소하면 두 복원선과 카드가 사라지고 HEAD → main → C0, 기록 0건이 됐다. 해결안을 feature 문장으로 변경하고 git add 이동 중 초기화해도 이전 제목·기록은 되살아나지 않았다. Git과 디스크 사이를 상단 탐색기 메뉴로 왕복했을 때도 각 초기 상태를 확인했다.
