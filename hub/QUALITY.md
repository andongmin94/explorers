# 모바일 재생 조작 수정 확인

해설을 가리고 모바일 Chromium에서 실제 재생 줄의 버튼을 눌렀다. 320px에서는 카드를 보던 위치에서 별도 스크롤 없이 정지 버튼을 터치하고, 카드가 버튼 위에 남는지 확인했다. 정지 중 배속을 변경한 뒤에는 같은 사건을 재개하고, 이전으로 돌아간 결과를 해당 단계에 직접 진입한 상태와 비교했다. [재생 중 실제 화면 여섯 장](scene-comparison.jpg)

| 탐색기 | 재현 단계 | 확인한 결과 |
| --- | --- | --- |
| 프로토콜 | UDP 3단계에서 6번 발신 직후, 7번 이동 중, 손실 순간에 각각 정지. ICMP 경로 추적에서 ‘다음 사건’ 후 정지·배속 변경·재개·이전 | 6만 출발했을 때 표는 6행이고 7·8 상세는 열리지 않는다. 7이 출발하면 행이 생기고 경로의 손실 지점에 X가 나타날 때 ‘손실’이 붙는다. ICMP는 ‘다음 사건’ 한 건을 실행할 때도 주 버튼이 ‘일시 정지’다. 한 번 눌러 좌표를 고정하고 1.5×로 재개하면 그 사건에서 멈춘다. 정지 후 이전은 해당 단계의 시작 상태를 유지한다. |
| CPU | RR 4ms, 9→10ms에 P1이 준비 큐에서 CPU로 가는 도중 정지. RR 1ms, 7→8ms의 세 차례 이동도 재생 | 320×568에서 P1은 화면 위에서 172~206px, 정지 버튼은 526~560px에 함께 보였다. 터치 후 좌표가 유지됐고 되감은 9ms의 위치·잔여 시간은 직접 이동과 같았다. RR 1ms에서도 P2의 SSD 복귀부터 마지막 P3 배정까지 카드가 버튼 위로 지나간다. |
| 메모리 | LRU 7번째 B의 부재 판정·C 교체·B 적재 중 배속 변경 및 정지. 마지막 B 적중의 값 반환 중 정지 | 2×로 재개한 같은 접근의 다음 프레임 선택은 약 0.75초(기본 1.5초)다. SSD에서 이동 중인 B를 멈춘 채 0.5×로 바꿔도 위치가 유지된다. 수동 재개는 기록 7회에서 멈추고 연속 재생은 8번째 E로 이어진다. 6번째로 되감으면 C와 F2 매핑이 복원된다. 마지막 B 값이 돌아오는 중에는 ‘이어서 재생’이 표시된다. |
| 트랜잭션 | 읽기부터 잠금 8번째 값 반환과 11번째 T2 커밋 응답, 교착 9번째 재개 도중 정지·배속 변경·이전 | 일반 읽기·잠금 읽기·교착에서 속도 변경은 현재 이동에 적용된다. 11번째에서 되감으면 10번째의 확정 9, 미확정 8, T2 잠금과 응답 점선의 행 포트가 직접 진입한 상태와 같다. 320×568에서 배속 버튼이 패널 안에 들어가고, 교착 화면은 두 클라이언트 이름과 A·B 행을 함께 볼 수 있다. |
| Git | 9번째 충돌 비교에서 C2를 인덱스로 보내다가 정지 → 2× → 재개 → C1 이동 중 0.5× → 이전. 3번째 add와 12번째 병합 커밋도 수동 재생 | 320×568에서 멈춘 C2는 94~117px, 버튼은 523~565px에 보였다. C2는 정지 위치를 유지하며 다음 C1도 2×를 이어받고, 이동 중 바꾼 0.5×도 곧바로 적용된다. 8번째로 되감으면 인덱스와 세 커밋이 복원된다. 수동으로 시작한 add는 3번째에 멈춘다. 12번째 진행 중 버튼은 ‘이어서 재생’이고 도착 뒤 C3의 두 부모는 C2·C1이다. |
| 디스크 | FCFS 3번째 183→37 탐색 도중 2×·정지·0.5×·이전·재생 | 320×568에서 바늘과 조작줄이 함께 보인다. 정지 중 배속을 변경해도 바늘은 같은 각도에 있다. 되감은 뒤에는 183·누적 130칸, 다시 도착하면 37·누적 276칸이다. |

통합 서버에서도 해설을 가리고 터치로 조작했다. UDP는 네트워크와 시퀀스 어디서 시작하든 정지 상태로 두 그림을 왕복하면 패킷 위치와 기록 수가 유지됐다. 손실 중 정지하고 이전으로 돌아가면 취소된 패킷과 손실 표시가 즉시 사라졌다. 디스크 대기 큐에서는 320px로 줄여도 ‘완료’ 두 글자가 같은 줄에 보였다.

기본 화면은 320×568과 390×844이고 프로토콜의 좁은 화면은 320×690이다. 자동 검사는 총 84개가 통과했다(프로토콜 28, CPU 17, 메모리 11, 트랜잭션 18, 디스크 3, Git 7).
