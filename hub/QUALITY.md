# 탐색기 학습 품질 재검수

2026년 11월 11일, 통합본의 여섯 탐색기와 트랜잭션 교착 시나리오를 Chromium에서 재생했다. 아래에는 이전 검수에서 어긋났던 순간과 수정 후 화면에서 확인한 결과를 기록했다.

## 송수신 방향과 패킷 해설

| 장면 | 화면에서 확인한 결과 |
| --- | --- |
| DHCP 임대 | 노트북은 OFFER를 받고 ACK가 이동하는 동안에도 미할당이다. ACK 도착 시 192.168.1.10/24로 바뀐다. 네트워크·시퀀스 보기, 단계 건너뛰기·되감기·초기화에서 같은 주소를 표시한다. |
| DHCP OFFER·ACK | 예시의 유니캐스트 응답은 라우터(MAC 끝 01)에서 노트북(끝 10)으로 간다. 검사기의 목적지·출발지와 이더넷 바이트의 앞 12바이트가 일치한다. [OFFER 검사 화면](dhcp-offer-inspector.png) |
| ACK 전송 중 회전 | 네트워크·시퀀스 보기에서 각각 정지한 뒤 390×844→844×390으로 회전하고 1.2초 기다렸다. 시퀀스 선은 약 30%에 멈췄고 화살촉과 임대 주소는 재개 후 도착할 때 나타났다. |
| UDP 음성 | 노트북에서 보낸 7번 프레임이 손실되면 미디어 서버가 20ms 공백을 보정한다. 첫 프레임 카드는 음성 80B와 RTP 헤더 12B를 구분한다. |
| IP·SMTP | IP 예시에서 라우터를 통과한 패킷의 TTL은 128에서 127로 바뀐다. SMTP는 수신 서버의 대기열 접수, 250 응답, 로컬 메일함 저장 순서로 보여 준다. |

## 일시정지·회전과 그림·해설 타이밍

| 재현 장면 | 멈춰서 확인한 내용 |
| --- | --- |
| 메모리 5번, D 접근 | 적재 직후에는 프레임에 D가 있지만 CPU는 아직 읽기를 마치지 않았다. 재시도와 값 전달을 거쳐 도착할 때 과정표가 완료된다. |
| 트랜잭션 잠금 읽기 8번·커밋 9번 | T2가 값을 받기 전에 계산 결과를 표시하지 않는다. 커밋 중 멈추고 너비를 바꿔도 확정값과 잠금은 그대로이고, 재생을 이어야 커밋이 끝난다. |
| 교착 6번·롤백 8번 | 두 번째 대기선이 연결되면 순환 대기를 설명한다. 롤백 중 회전해도 T2의 잠금과 미확정값은 해당 단계에서 유지되며, 재생을 이으면 롤백이 한 번 기록된다. |
| Git add·병합 충돌 | git add 중 회전해도 기록은 2건이다. 병합 중에는 C0가 인덱스에 도착하고 C2가 이동하는 시점에서 멈췄다. 회전 직후에도 인덱스에는 C0 한 줄, 기록에는 8건이 남았다. 재개 후 C2·C1과 충돌 표식이 차례로 도착했다. 해결안을 골라 C3의 부모 C2·C1까지 확인했다. |

메모리와 트랜잭션은 재생 중 720→390→760px로 두 번 바꿔도 메모리 접근·커밋·롤백이 각각 한 번만 완료됐다. Git은 390×844에서 844×390으로 회전한 전후에 브라우저가 보고한 애니메이션 경과 시간과 경로 진행률이 같았다.

## 모바일 가시성·디스크 경로·CPU 배속

- 390×844에서 CPU의 P2와 디스크 SSTF의 65번을 예측하고 확인을 눌렀다. CPU 장면 766px와 디스크 장면 532px가 첫 이동부터 뷰포트에 들어왔다. 터치·키보드로 확인했으며 모션 감소 설정에서도 도착 상태를 확인했다.
- 디스크 SSTF 53→65에서 선택한 카드 중심과 점선, 점선 끝과 컨트롤러 포트가 데스크톱·모바일 모두 0.1px 이내로 일치했다. 헤드 이동 중 선택한 2×가 현재 이동에 적용됐다.
- 디스크 FCFS 53→98에서도 요청 카드를 멈추고 화면을 바꿨다. 1440→390px로 바꿀 때 포트에서 371.61px 벗어나던 종점 오차가 0.001px 미만으로 줄었다. 정지 중에는 헤드 53·기록 0건을 유지했고 재개 후 98번 트랙에 도착해 45칸을 더했다.
- CPU 2ms에서는 P3 도착 → P1 선점 → P2 배정 순서로 작업표·해설·기록이 바뀌었다. 4ms에서 1×를 2×로 올렸을 때 P3의 CPU 사용량은 0.4→0.5ms, P2의 남은 입출력 시간은 2.6→2.5ms로 진행했다. 수동 한 단계는 한 번 눌러 멈출 수 있고, 재개하면 그 단계 끝에서 멈춘다.
- CPU의 세 이동을 각각 일시정지한 뒤 390→844→1440→390px로 화면을 바꿨다. 각 카드의 경로 진행률과 사건 기록은 그대로였고 이동을 마쳤을 때만 기록이 6건이 됐다. 이동 중에는 작은 카드에 작업 ID를, 도착하면 전체 이름과 남은 시간을 표시한다.
- Git 병합에서는 세로 화면에 출발 커밋과 인덱스가 함께 들어왔다. 짧은 가로 화면에서는 이동 중인 카드를 따라가고, 충돌 표식이 도착하면 작업 파일이 보였다.

각 소스 저장소의 자동 검사 81개가 통과했다. 프로토콜 25개, CPU 17개, 메모리 11개, 트랜잭션 18개, 디스크 3개, Git 7개다. 모바일 검증은 Chromium의 모바일 화면과 터치 입력 에뮬레이션으로 진행했다.
